# Ansible

Ansible configures the range VMs. It runs only in the `tools` container (ansible-core 2.17, pywinrm, collections
from `docker/tools/requirements.yml`).

## Requirements

1. The Elastic stack is running (`docker compose --env-file .env up -d` in `docker/`) and the Fleet policies
   `range-windows` / `range-linux` exist (preconfigured in `docker/elastic/kibana.yml`).
2. The VMs have been created with Terraform, and `ansible/inventory/range.yml` has been generated by
   `scripts/configure.py` from `range.yaml`: groups `windows`, `linux`, `dc`, `server`, `client`,
   `linux_server`, `attacker`, the service groups `ca`, `web`, `fileserver`, `sql`, `identity_connector` and
   the topology variables `range_*` (see [Configuration](configuration.md#ansible-variables-from-the-inventory)).
3. `docker/.env` contains `ELASTIC_VERSION`, `ELASTIC_PASSWORD`, `RANGE_ADMIN_PASSWORD`, `RANGE_DSRM_PASSWORD`,
   `RANGE_USER_PASSWORD`, `RANGE_TIER0_PASSWORD` and the agent user passwords `RANGE_BLUE_PASSWORD`,
   `RANGE_RED_PASSWORD`, `RANGE_ORCH_PASSWORD`. Secrets are never stored in the repository; roles read them with
   `lookup('env', ...)`.
4. Internet access from the range network (Sysmon, sysmon-modular configuration, Elastic Agent artifacts, apt).

## Running

From `docker/`:

```sh
# complete range
docker compose --env-file .env run --rm tools sh -c "cd ansible && ansible-playbook site.yml"

# a single phase
docker compose --env-file .env run --rm tools sh -c "cd ansible && ansible-playbook playbooks/ad.yml"

# connectivity check
docker compose --env-file .env run --rm tools sh -c "cd ansible && ansible windows -m ansible.windows.win_ping && ansible linux -m ping"
```

If the repository is in a world-writable directory (for example a bind mount from Windows), Ansible ignores
`ansible.cfg` in the current directory. The `tools` container therefore sets
`ANSIBLE_CONFIG=/work/ansible/ansible.cfg`.

## Order (`site.yml`)

| # | Playbook | Hosts | Roles |
|---|---|---|---|
| 1 | `playbooks/ad.yml` | `dc` | `ad_forest`, `ad_objects` |
|   |  | `windows:!dc` | `domain_join` |
|   |  | `ca` / `web` / `fileserver` / `sql` | `adcs` / `iis` / `fileserver` / `sql` (placeholder) |
| 2 | `playbooks/base.yml` | `windows` | `ca_trust`, `win_base`, `sysmon` |
|   |  | `linux` | `ca_trust`, `linux_base` |
| 3 | `playbooks/elastic-config.yml` | `localhost` (Kibana/ES API) | `elastic_fleet_config`, see [Elastic](elastic.md) |
| 4 | `playbooks/agents.yml` | `windows:linux_server` | `elastic_agent` or `sentinelone_agent` (depending on `AIRANGE_EDR`) |
| 5 | `playbooks/kali.yml` | `attacker` | `kali` |

AD comes first because the DC is the DNS server of all other range VMs (apt, downloads and the domain join need
it). Every playbook can run on its own and is idempotent.

Not part of `site.yml`:

| Playbook | Purpose |
|---|---|
| `playbooks/vulns.yml` | Vulnerability profiles, see [Vulnerability profiles](vulnerability-profiles.md) |
| `playbooks/s1-identity.yml`, `s1-logcollection.yml`, `s1-policy.yml` | SentinelOne configuration, see [SentinelOne](sentinelone.md) |

## Roles

| Role | Purpose |
|---|---|
| `ca_trust` | Elastic CA (`/certs/ca/ca.crt` in the container) into LocalMachine\Root or `/usr/local/share/ca-certificates` |
| `win_base` | Time zone, PowerShell script block/module logging and transcription, advanced audit policy including command line in 4688, Security log 512 MB, RDP |
| `sysmon` | Sysmon (Sysinternals) with the olafhartong/sysmon-modular `sysmonconfig.xml`; configuration update on change |
| `ad_forest` | Forest `range_domain` (NetBIOS `range_netbios`), DNS forwarder = gateway, reverse zone from `range_cidr` |
| `ad_objects` | OUs Tier0/Servers/Workstations/Users/Groups/ServiceAccounts, 30 employees, department groups `GG_*`, admins `adm.*` (Domain Admins), service accounts `svc.*` |
| `domain_join` | DNS to the DC, join into OU Servers or Workstations, reboot |
| `adcs` | Enterprise root CA on the `ca` host (web enrollment optional, off by default) |
| `iis` / `fileserver` / `sql` | IIS with default site / share `Data` with department folders / placeholder |
| `elastic_agent` | Enrollment token through the Fleet API, install and enroll Elastic Agent `ELASTIC_VERSION` |
| `sentinelone_agent` | SentinelOne agent instead of Elastic Agent (`AIRANGE_EDR=sentinelone`) |
| `linux_base` | Base packages, time zone, removes `auditd` (conflicts with auditd_manager) |
| `kali` | Attack tools (impacket, netexec, bloodhound-python, responder, evil-winrm, nmap, certipy-ad, john, hashcat, rockyou) and the egress guard (nftables table `airange_guard`) |
| `elastic_fleet_config` | Elastic configuration as code, see [Elastic](elastic.md) |
| `sentinelone_*` | SentinelOne identity, log collection and agent policy, see [SentinelOne](sentinelone.md) |
| `vuln_*` | Intentional vulnerabilities for the scenarios, via `playbooks/vulns.yml` |

## Credentials

- **Windows:** WinRM HTTP 5985, NTLM (message encryption), local `Administrator` / `RANGE_ADMIN_PASSWORD`. On the
  DC this becomes the domain Administrator after promotion; the domain join and the enterprise CA use
  `Administrator@<domain>`.
- **Linux:** SSH, user `range` / `RANGE_ADMIN_PASSWORD` (sudo).
- **AD users:** `RANGE_USER_PASSWORD` (set only when the account is created). Tier-0 admins `adm.*` use their own
  `RANGE_TIER0_PASSWORD` (reset when it differs), so spraying the user password does not lead straight to
  Domain Admin.

## Limitations

- Audit subcategories are set by their English names (English OS templates).
- Elastic Agent is installed only if the service is missing; upgrades go through Fleet.
- Sysmon is not updated automatically (the zip is downloaded once). If needed, delete
  `C:\ProgramData\ai-range\sysmon` and uninstall Sysmon.
- Computers that are already joined are not moved to another OU.
