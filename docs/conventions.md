# Reference

Conventions that apply to all components, plus the default values of the example topology. Names, networks and
IPs always come from `range.yaml` ([Configuration](configuration.md)); the values below are the defaults from
`range.example.yaml`.

**Never hard-code host names or IPs.** Ansible uses groups and the `range_*` variables, the agents use
`agents/airange/topology.py`, Terraform and Packer use `yamldecode(range.yaml)`.

## Network and hosts

- Proxmox cluster without HA. Example: nodes `pve1` (10.0.10.11) and `pve2` (10.0.10.12), management on
  `vmbr0`.
- Range: one VLAN on the bridge (example: VLAN 21 on `vmbr0`), network 10.0.21.0/24, gateway/router 10.0.21.1.
  The VLAN has DHCP (for Packer builds); range VMs get static IPs via cloud-init / cloudbase-init.
- Controller (management, Docker): `controller.ip` from `range.yaml` (example 10.0.10.5), available to Compose
  as `CONTROLLER_IP` in `docker/range.env`. Fleet: `https://<controller.ip>:8220`, Elasticsearch: `:9200`,
  Kibana: `:5601`.
- No router or firewall inside the range. Internet access from the range network is allowed.

## Active Directory

- Domain and NetBIOS name from `range.yaml` (example `corp.internal` / `CORP`). The DC is the DNS server for all
  domain members.
- DNS forwarder on the DC: the gateway (`network.gateway`).

## Ansible inventory

Generated by `scripts/configure.py` as `ansible/inventory/range.yml`:

- OS groups: `windows`, `linux`. Role groups: `dc`, `server`, `client`, `linux_server`, `attacker`. Service
  groups: `ca`, `web`, `fileserver`, `sql`, `identity_connector`. Topology as `all.vars` (`range_*`).
- Host var `ansible_host` = IP. Host names as in `range.yaml`.

- All templates: VirtIO drivers, qemu-guest-agent, disk `scsi0` (virtio-scsi-single), virtio NIC on the range
  bridge and VLAN.
- Windows: cloudbase-init (ConfigDrive, applies the static IP from Proxmox cloud-init), OVMF + vTPM 2.0 + Secure
  Boot, WinRM enabled (HTTP 5985), local `Administrator` with `RANGE_ADMIN_PASSWORD`.
- Linux: cloud-init (NoCloud), user `range` with `RANGE_ADMIN_PASSWORD`, sudo NOPASSWD, SSH enabled.

## Tooling

- Everything runs in the `tools` container (`docker/compose.yml`, service `tools`): Terraform 1.9.8, Packer
  1.11.2, ansible-core 2.17, pywinrm, xorriso, jq. The repository is mounted at `/work`, the Elastic CA at
  `/certs/ca/ca.crt`.
- Invocation from `docker/`: `docker compose --env-file .env run --rm [--service-ports] tools <cmd>`.
- The container is attached to the Compose network: `https://kibana:5601` and `https://es01:9200` are reachable
  directly.
- Packer HTTP server: ports 8100-8110, published via `--service-ports`, `http_bind_address 0.0.0.0`; VMs reach it
  through `controller.ip` (Packer `local.http_ip`).
- Environment in the `tools` container: `PROXMOX_VE_API_TOKEN`, `PROXMOX_VE_INSECURE`, `ELASTIC_VERSION`,
  `ELASTIC_PASSWORD`, `CONTROLLER_IP` / `PROXMOX_VE_ENDPOINT` (from `docker/range.env`), `RANGE_ADMIN_PASSWORD`,
  `RANGE_DSRM_PASSWORD`, `RANGE_USER_PASSWORD`, `RANGE_TIER0_PASSWORD`, the agent user passwords and the
  SentinelOne variables.
- Secrets never go into the repository; always read them from the environment (Packer: `env()`, Ansible:
  `lookup('env', ...)`).

## Elastic

- Fleet policies (preconfigured in `docker/elastic/kibana.yml`): `range-windows`, `range-linux`,
  `fleet-server-policy`.
- Agents on the VMs trust the CA through the system trust store (the CA is installed by Ansible).
- Elastic Agent version = `ELASTIC_VERSION`.

## Proxmox helpers

`scripts/proxmox/`, API only, no SSH:

| Script | Purpose |
|---|---|
| `screenshot.py <node> <vmid> <out.png>` | Console screenshot (VNC over the API WebSocket) |
| `sendtext.py <node> <vmid> "<text>"` | Keyboard input (US layout, `\n` = Enter) |
| `guestexec.py [--windows] <node> <vmid> '<cmd>'` | Run a command through the qemu-guest-agent (root/SYSTEM) |
| `download-isos.sh` | Download the installer ISOs on a node (run on the node as root) |

Environment: `PROXMOX_VE_ENDPOINT`, `PROXMOX_VE_API_TOKEN`. In the `tools` container:
`python /work/scripts/proxmox/<script> ...`.
